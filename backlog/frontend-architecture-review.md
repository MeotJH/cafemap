# 프론트엔드 아키텍처 리뷰

## 목표

- 현재 `front/` 구조가 어떤 아키텍처 성격을 가지는지 파악한다.
- 객체지향 구조, 레이어드 아키텍처, MVVM 적용 정도를 판단한다.
- 디자인 패턴과 유지보수성, 가독성 측면의 강점과 약점을 정리한다.
- 필요한 경우 `memory/frontend.md`에 프론트엔드 설계 및 코드스타일 규약을 추가한다.

## 작업 단위

### FAR1. 구조 파악

- `front/lib` 디렉터리 구조 확인
- `app`, `core`, `domain`, `data`, `presentation` 책임 구분 확인

### FAR2. 상태관리와 화면 흐름 파악

- `presentation/providers` 구조 확인
- 페이지에서 provider와 repository를 어떻게 사용하는지 확인

### FAR3. 아키텍처 판단

- layered architecture 성격 판단
- MVVM 적용 여부 판단
- 객체지향성 및 패턴 사용 여부 판단

### FAR4. 유지보수성 판단

- 대형 파일, 책임 혼합, 읽기 어려운 지점 확인
- 클래스/함수 주석 규약 준수 여부 확인

### FAR5. 규약 보강

- 필요 시 `memory/frontend.md`에 설계 및 코드스타일 규약 추가

## 완료 기준

- 현재 프론트엔드 구조를 설명할 수 있다.
- 적용된 아키텍처의 성격과 한계를 구분해서 말할 수 있다.
- 유지보수 규약이 부족하면 `memory/frontend.md`에 반영되어 있다.
