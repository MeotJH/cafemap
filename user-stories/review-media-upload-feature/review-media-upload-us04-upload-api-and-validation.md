# US-04: 미디어 업로드 API와 서버 검증 확장

## 사용자 스토리

백엔드 관점에서 사진과 영상을 안전하게 업로드·저장하고 싶다. 그래야 프론트 확장 후에도 서버가 일관된 검증 규칙을 유지할 수 있다.

## 범위

- presigned upload API를 사진/영상 모두 지원하도록 확장한다.
- 리뷰 create/update validation을 미디어 항목 기준으로 바꾼다.
- 개수 제한, MIME 타입, 파일 크기, URL 유효성 검증을 정의한다.
- 영상 썸네일 저장 방식이 필요하면 함께 설계한다.

## Frontend Tasks

- 업로드 요청 시 파일 타입에 따라 content type을 정확히 전달한다.
- 영상 썸네일이 별도 업로드라면 연쇄 업로드 순서를 맞춘다.

## Backend Tasks

- presign endpoint에서 허용 MIME 타입을 확장한다.
- 리뷰 저장 검증을 `mediaItems` 중심으로 변경한다.
- 이미지/영상 합산 최대 5개 검증을 서버에서 강제한다.
- 필요 시 영상과 썸네일 prefix 정책을 분리한다.
- 테스트에 5개 허용, 6개 거절, 허용되지 않은 타입 거절 케이스를 추가한다.

## Designer Tasks

- 없음. 단, 서버 오류 메시지 문구가 사용자에게 노출되면 제품 문구 검토가 필요하다.

## 계약 및 의존성 노트

- 업로드 정책은 클라이언트와 서버가 모두 같은 MIME 타입 집합을 써야 한다.
- 1차에서는 영상 트랜스코딩 없이 원본 업로드 정책으로 갈 가능성이 높다.

## Acceptance Criteria

- 서버가 사진/영상 혼합 업로드를 검증하고 저장한다.
- 서버에서 개수 초과, 타입 불일치, URL 불량을 거절한다.
- presign API가 영상 업로드에도 동작한다.
