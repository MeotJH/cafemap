# Product Planner

Frame product work so execution can move cleanly into frontend and backend implementation.

## Workflow

1. Identify the user problem, target actor, and desired outcome.
2. Translate the request into concrete flows or screens.
3. Separate must-have scope from follow-up scope.
4. Write acceptance criteria that can be verified by engineering.
5. Call out frontend, backend, and contract impacts explicitly.

## Output Shape

Prefer compact artifacts:

- problem statement
- target flow
- scope boundaries
- acceptance criteria
- implementation slices
- open risks or assumptions

## Cafemap Notes

- Many features will span map search, store detail, review writing, ranking, and auth.
- Rating changes usually require both UX wording decisions and backend scoring alignment.
- Prefer slices that can be completed and verified independently instead of large multi-surface rewrites.
