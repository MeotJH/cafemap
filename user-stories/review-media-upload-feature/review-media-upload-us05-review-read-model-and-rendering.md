# US-05: 리뷰 조회 응답과 소비 화면의 미디어 렌더링

## 사용자 스토리

리뷰를 보는 사용자로서 사진과 영상을 구분해서 볼 수 있어야 한다. 그래야 작성자가 남긴 정보를 제대로 소비할 수 있다.

## 범위

- 리뷰 상세/내 리뷰/매장 리뷰 응답에 미디어 항목을 포함한다.
- 프론트는 미디어 타입별로 이미지 또는 영상 플레이어/프리뷰를 렌더링한다.
- 영상은 자동재생 없이 탭하여 재생한다.

## Frontend Tasks

- 리뷰 엔티티와 UI 컴포넌트가 `mediaItems`를 소비하도록 바꾼다.
- 영상은 재생 전 썸네일 또는 플레이스홀더를 보여준다.
- 구형 데이터(`imageUrls`만 존재) fallback 렌더링을 유지한다.

## Backend Tasks

- 리뷰 응답 DTO에 미디어 타입 정보와 선택 필드를 포함한다.
- 구형 리뷰를 새 응답 구조로 읽을 때 fallback 변환을 제공한다.

## Designer Tasks

- 상세 화면/리스트 화면에서 영상 노출 우선순위를 정한다.
- 썸네일 비율, 재생 버튼 스타일, 재생 실패 상태를 정의한다.

## 계약 및 의존성 노트

- 1차에서 목록 화면은 첫 미디어만 보여줄지, 여러 개를 스와이프 가능하게 할지 결정이 필요하다.
- 썸네일이 없을 때의 fallback UI가 필요하다.

## Acceptance Criteria

- 리뷰 조회 응답에서 미디어 타입을 구분할 수 있다.
- 프론트가 이미지와 영상을 각각 알맞게 렌더링한다.
- 구형 사진 리뷰도 깨지지 않는다.

## Verification Notes

- 상세 화면, 내 리뷰, 매장 리뷰 목록에서 각각 렌더링 확인
- 구형 이미지 전용 리뷰 fallback 확인
