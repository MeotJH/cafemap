# US-01: 리뷰 미디어 계약과 첨부 규칙 정의

## 사용자 스토리

서비스 운영자로서 리뷰 첨부 규칙과 API 계약을 먼저 명확히 정의하고 싶다. 그래야 프론트와 백엔드가 같은 모델로 사진/영상을 처리할 수 있다.

## 범위

- 리뷰 첨부 단위를 사진 URL 배열에서 미디어 항목 배열로 확장한다.
- 첨부 제한을 `사진/영상 합산 최대 5개`로 정의한다.
- 허용 미디어 타입, 파일 크기, 영상 길이 초안 정책을 정한다.
- 기존 `imageUrls` 응답과의 호환 전략을 정한다.

## Frontend Tasks

- 리뷰 엔티티와 repository 계약에서 미디어 항목 모델 초안을 반영한다.
- 작성/수정/상세 화면이 어떤 필드를 필요로 하는지 정리한다.
- 구형 `imageUrls`만 오는 경우의 fallback 표현 방식을 정리한다.

## Backend Tasks

- 리뷰 create/update/read 스키마에 미디어 항목 계약을 정의한다.
- 저장 모델을 `image_urls_json`에서 확장하거나 신규 필드로 옮길지 결정한다.
- 기존 데이터 조회 시 `imageUrls -> mediaItems(image)` 변환 fallback을 정의한다.

## Designer Tasks

- "사진/영상 최대 5개" 문구를 확정한다.
- 영상 배지, 썸네일, 재생 아이콘 최소 표현 규칙을 정한다.
- 제한 초과/업로드 실패/지원하지 않는 형식에 대한 문구 톤을 정한다.

## 계약 및 의존성 노트

- 프론트/백엔드가 공통으로 사용할 필드명 결정이 선행되어야 한다.
- 1차 권장 계약:
  - `mediaItems: [{ type, url, thumbnailUrl, durationMs, sortOrder }]`
- 하위 호환이 필요하면 응답에 `imageUrls`를 임시 유지한다.

## Acceptance Criteria

- 미디어 항목 구조와 제한 정책이 문서로 고정된다.
- 프론트/백엔드에서 동일한 필드명과 타입 값을 사용한다.
- 5개 제한이 "사진만 5개"가 아니라 "사진/영상 합산 5개"로 명확히 표현된다.

## Verification Notes

- feature brief와 후속 user story의 용어가 동일한지 확인한다.
- 프론트 모델/백엔드 스키마 초안에서 필드 mismatch가 없는지 검토한다.
