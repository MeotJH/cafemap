# US-04: 랭킹 화면에 목적 모드 표시

## 사용자 스토리

방문자로서 랭킹 화면에서 내가 선택한 목적을 명확히 알고 싶다. 그래야 현재 리스트가 어떤 기준으로 정렬된 것인지 이해할 수 있다.

## 범위

- 랭킹 화면이 `purpose` query parameter를 읽는다.
- 목적이 있으면 제목과 설명을 목적별로 바꾼다.
- 목적이 없으면 기존 랭킹 화면을 유지한다.
- 목적 선택 상태를 화면 상단에 표시한다.

## 화면 문구 예시

- `데이트에 좋은 카페`
- `대화하기 좋은 카페`
- `사진 찍기 좋은 카페`
- `커피맛 좋은 카페`
- `오래 앉기 좋은 카페`

## 프론트 영향

- 랭킹 홈 또는 랭킹 상세 route 구조 확인 필요
- 랭킹 provider가 목적 값을 받을 수 있어야 한다.
- 기존 `RankingAudience`와 목적 mode가 충돌하지 않게 모델링한다.

## 백엔드/계약 영향

- 목적 mode는 `/store-rankings?purpose=...` 결과를 사용한다.

## 역할별 할 일

### Frontend

- 랭킹 화면이 `purpose` query parameter를 읽도록 한다.
- 목적이 있으면 제목, 설명, 정렬 의미를 목적 기준으로 바꾼다.
- 목적이 없으면 기존 랭킹 화면을 유지한다.

### Backend

- 목적 mode에 대응하는 응답 계약은 기존 `StoreRankingOut` shape를 유지한다.

### Designer

- 목적별 제목과 설명 문구를 확정한다.
- 목적 모드와 기존 부부픽/아내픽/남편픽 필터가 함께 있을 때 정보 위계를 정한다.

## 수용 기준

- 목적이 있는 랭킹 화면은 목적별 제목을 보여준다.
- 목적이 없는 기존 랭킹 화면은 기존 동작을 유지한다.
- 새로고침해도 query parameter 기준으로 같은 화면이 복원된다.

## 검증 메모

- `flutter analyze`
- `/rankings?purpose=date` 등으로 직접 진입해 문구와 상태가 맞는지 확인한다.
