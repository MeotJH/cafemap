# US-11: 목적 랭킹 빈 상태와 fallback 처리

## 사용자 스토리

방문자로서 특정 목적의 데이터가 부족해도 앱이 어색하게 깨지지 않았으면 한다. 그래야 추천 결과를 신뢰하고 다른 목적을 선택할 수 있다.

## 범위

- 목적 점수 계산 결과가 비어 있을 때 빈 상태를 보여준다.
- 일부 데이터만 있을 때는 fallback 정렬을 사용한다.
- 목적 key가 잘못됐을 때 안전하게 처리한다.

## 프론트 영향

- 목적 랭킹 화면의 loading, error, empty state 문구 추가
- 목적별 데이터가 부족한 경우 안내 문구 추가

## 백엔드/계약 영향

- 목적 점수가 0인 항목을 포함할지 제외할지 정책 필요
- 잘못된 purpose 처리 정책 필요

## 제안 정책

- 지원하지 않는 purpose는 400보다 프론트 fallback이 쉬운 기본 랭킹 반환을 우선 검토한다.
- 지원하는 purpose지만 점수 데이터가 부족하면 `displayScore`와 `reviewCount`로 보조 정렬한다.

## 역할별 할 일

### Frontend

- loading, error, empty state를 구분해서 보여준다.
- 사용자가 다른 목적을 다시 선택할 수 있게 화면이 막히지 않게 한다.

### Backend

- 데이터 부족 시 빈 리스트 또는 fallback 정렬 정책을 일관되게 유지한다.
- 잘못된 purpose의 처리 정책을 구현한다.

### Designer

- 빈 상태 문구와 오류 문구 톤을 정한다.
- 목적이 실패했을 때 사용자가 다음 행동을 이해할 수 있게 상태 문구를 정리한다.

## 수용 기준

- 목적 랭킹 결과가 0개여도 앱이 깨지지 않는다.
- 네트워크 오류와 빈 데이터가 구분된다.
- 사용자가 다른 목적을 다시 선택할 수 있다.

## 검증 메모

- purpose 데이터가 없는 상태를 강제로 만들어 빈 화면과 에러 화면이 구분되는지 확인한다.
